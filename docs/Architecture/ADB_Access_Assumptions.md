# ADB_Access_Assumptions.md

> 文档类型：Architecture Assumption（阶段性冻结）
> 适用阶段：Phase 1 – Minimal Closed Loop
> 目标：为 SnVerify 项目在 Phase 1 阶段提供**明确、不可歧义的 ADB 访问与 SN 读取约束**，避免实现分叉与 AI 误推理。

---

## 1. 文档目的

本文件用于明确说明：

* Phase 1 阶段 **唯一被允许的 ADB 访问方式**
* SN 读取所需的 **严格命令顺序**
* 可接受 / 不可接受的失败处理策略

本文件属于 **“阶段性事实源”**：

* 在 Phase 1 内视为**冻结假设**
* 后续阶段（Phase 2+）允许被推翻或扩展

---

## 2. ADB 工具前提假设

* 上位机程序 **自带 adb 工具**（随程序打包分发）
* 不依赖系统环境变量中的 adb
* 不要求用户手动配置 adb

---

## 3. SN 读取的唯一合法流程（Phase 1）

在 Phase 1 中，**读取设备 SN 必须严格按以下顺序执行**：

### Step 1：打开设备访问权限

```bash
adb shell ylzero
```

说明：

* 该命令用于通过设备侧密钥或权限校验
* **必须先执行**，不得跳过
* 不允许并发执行

### Step 2：读取设备 SN

```bash
adb shell getprop sys.skyroam.osi.sn
```

说明：

* 该命令用于获取设备唯一 SN
* 返回值为空 / 异常 / 执行失败，均视为读取失败

---

## 4. 顺序与并发约束（硬规则）

以下行为在 Phase 1 中 **明确禁止**：

* 合并两条 adb 命令执行
* 并发执行多条 adb shell 命令
* 在未成功执行 `ylzero` 前直接读取 SN
* 在同一校验流程中对多个设备执行 adb

**结论性规则：**

> 一个 SN 校验流程中，只允许串行执行一组 adb 命令。

---

## 5. 失败与超时策略（Phase 1）

* adb 命令执行失败 / 超时：

  * 允许有限次数重试（策略由 Service 层定义）
  * 超出重试次数 → 判定为 FAIL / TIMEOUT

* SN 为空或非法值：

  * 不进入比对流程
  * 直接作为校验失败记录

* 所有失败结果：

  * **必须被记录并持久化**
  * 不允许静默丢弃

---

## 6. 与架构分层的关系

* ADB 调用逻辑 **仅允许存在于 Service / IO 层**
* ViewModel / UI 层：

  * 不得直接调用 adb
  * 不感知 adb 命令细节

---

## 7. 演进声明

* 本文件仅对 Phase 1 生效
* 以下情况可能触发本假设失效：

  * 新设备型号引入
  * SN 存储位置变化
  * ADB 权限模型调整

任何修改，必须：

* 明确标注新阶段
* 不影响既有 Phase 1 数据可追溯性
