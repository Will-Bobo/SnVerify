# SnVerify Phase 2.5 UI 与数据逻辑确认清单

## 文档目的

本清单用于记录 Phase 2.5 阶段 UI 与数据逻辑的所有关键决策点，供团队成员、Cursor Agent 和未来迭代参考。所有内容均基于人工 review 与讨论确定，保证功能闭环。

---

## 关键决策点

### 1. 订单与 Session

1. 一个订单允许存在多个 Session，每次点击“开始测试”生成新 Session。 ✅
2. 同一订单允许跨天测试。 ✅
3. 订单导出保持每个 Session 单独文件，每个 Session 内包含两张 Sheet：PASS / FAIL。 ✅
4. 每个订单只绑定一个项目（Project），绑定后不可修改。 ✅
5. ProjectName 与 OrderName 输入约束：禁止文件系统特殊字符，长度上限 64 个，不允许中文。 ✅
6. 导出时若目标文件已存在，弹窗由操作员选择覆盖或取消。 ✅
7. SessionId 命名唯一性：严格禁止同一秒内重复生成 Session。 ✅
8. 未结束的 Session（EndTime = null）在导出时包含，并标记为“未完成 / 异常”。 ✅

### 2. 测试记录 TestRecord

9. TestRecord 不冗余存储 Project / Order，通过 Session 关联。 ✅
10. 失败 SN 可以重测，每次生成新的 TestRecord，历史保留。 ✅
11. FAIL Sheet 导出去重，使用 (StickerSN + DeviceSN) 作为联合主键，PASS Sheet 不去重。 ✅
12. 扫码枪输入必须完整回车或人工点击触发检验。 ✅
13. FAIL / PASS 检验结果在检验区拟物化、立体感突出显示，等待状态为灰色。 ✅
14. 日志区域默认隐藏，打开后显示最近 3000 条，压力测试后再优化。 ✅
15. 扫码枪输入法自动切换为英文，确保输入合法。 ✅
16. 扫码输入框暂保持可见，实时显示内容，未来可优化为隐藏 / 弱化 TextBox，由 ScanInputService 接管。 ✅
17. 自动检验按钮仅执行快速自检（ADB / MES），等待当前 SN 处理完成再触发。 ✅
18. 状态栏显示精简信息：当前 Order、Processing 状态、最近检验结果。 ✅
19. 窗口固定尺寸 H:800, W:1300，布局固定，UI 简洁稳定。 ✅
20. 测试记录区一次性显示当前 Session 全部记录，默认隐藏，打开后显示当前 Session。 ✅
21. FAIL Sheet 去重，PASS Sheet 不去重，保持完整审计。 ✅
22. Session 导出 Excel 文件名包含 OrderName + SessionId，例如 `Order_20260127_001_20260127_091532.xlsx`。 ✅
23. 日志文件命名与数据文件一致，仅后缀不同，保持 .txt 格式。 ✅
24. 重测记录在日志文件中全部保留，每个操作记录都有。 ✅
25. 检验区显示最新结果即可，不显示历史累积 SN。 ✅
26. 设备异常（ADB 无法读取）在界面错误提示区显示，同时记录日志。 ✅
27. MES 异常在界面错误提示区显示并记录日志，不写入 PASS/FAIL Sheet。 ✅
28. 重复扫描 SN 时，界面提示“设备 SN 已存在”，连续重复显示仅保留一条。 ✅
29. 自动检验按钮等待当前处理完成再执行，避免覆盖或并行冲突。 ✅
30. 日志区显示所有错误记录，滚动显示，避免遗漏。 ✅
31. 重复点击 Start / End 按钮，界面提示操作员并忽略后台重复触发，额外判断是否有实际 TestRecord 生成。 ✅
32. 当日志或测试记录展示时，当前设计最近 3000 条，压力测试后再优化。 ✅
33. 未来优化隐藏 / 弱化 TextBox，由 ScanInputService 接管，当前阶段保持可见。 ✅
