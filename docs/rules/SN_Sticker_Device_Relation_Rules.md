# SN / 包装 / 设备 关系校验规则（工程冻结版）

> 文件用途：
>
> * 作为 **SnVerify 上位机** 中 SN 校验逻辑的**唯一事实来源**
> * 供 **开发人员 / Cursor Agent / 测试人员 / 工艺人员** 统一理解与执行
> * 本文档冻结后，不得在实现层随意“脑补规则”

---

## 1. 设计目标（Why）

本上位机系统的核心目标只有一个：

> **保证所有成功出站（PASS）的设备，其 StickerSN（包装 SN） 与 DeviceSN（设备 SN）
> 之间的绑定关系是：唯一、正确、可追溯、不可重复的。**

系统存在的意义不是“尽量放行”，而是：

* 防止包装错贴
* 防止重复出站
* 防止合格 SN 被错误复用
* 为产线质量追溯提供可靠事实

---

## 2. 基本定义（统一术语）

### 2.1 SN 类型

* **StickerSN**：

  * 设备外包装 / 标签上的条码 SN
  * 成本低，可更换

* **DeviceSN**：

  * 设备内部读取的 SN（如 ADB 读取）
  * 成本高，不可随意更换

### 2.2 绑定关系（Binding）

* 一次校验流程的核心产物
* 表示：

```
StickerSN  <->  DeviceSN
```

### 2.3 历史事实的唯一来源

> **只有 PASS 过的绑定记录，才被认为是“已发生的历史事实”。**

* PASS：进入历史绑定表（事实层）
* FAIL：仅作为过程日志，不参与任何重复判断

---

## 3. 全局设计原则（非常重要）

### 原则 1：PASS 是唯一事实

* 所有“是否重复”的判断：

  * **只查询历史 PASS 绑定记录**
* FAIL 记录：

  * 不参与重复判断
  * 不影响后续重测

---

### 原则 2：已 PASS 的绑定不可被任何方式覆盖

* StickerSN 或 DeviceSN 只要已出现在 PASS 绑定中：

  * 即视为已出站
  * 不允许再次绑定

---

### 原则 3：异常处理优先牺牲 StickerSN

在无法明确判断责任时：

* 优先判定为 **贴纸问题**
* 因为：

  * 贴纸成本最低
  * 更换风险最小

---

## 4. 冻结的校验规则（执行级）

以下规则 **按顺序判断，命中即返回，不再继续向下判断**。

---

### 规则 1️⃣：绑定一致，且无历史 PASS 绑定 → PASS

**条件：**

* StickerSN == DeviceSN
* StickerSN ∉ 历史 PASS 绑定表
* DeviceSN ∉ 历史 PASS 绑定表

**结论：**

* PASS

**含义：**

* 首次正确绑定
* 合法出站

---

### 规则 2️⃣：绑定一致，但存在历史 PASS 绑定 → FAIL（已出站）

**条件：**

* StickerSN == DeviceSN
* StickerSN ∈ 历史 PASS 绑定表

**结论：**

* FAIL

**错误类型：**

* `AlreadyPassed`

**含义：**

* 已合格出站的设备或包装被重复扫描

---

### 规则 3️⃣：绑定不一致，StickerSN 已存在于历史 PASS 绑定中 → FAIL（贴纸重复）

**条件：**

* StickerSN != DeviceSN
* StickerSN ∈ 历史 PASS 绑定表

**结论：**

* FAIL

**错误类型：**

* `StickerSN_Reused`

**操作指引：**

* 废弃当前贴纸
* 更换新的 StickerSN

---

### 规则 4️⃣：绑定不一致，DeviceSN 已存在于历史 PASS 绑定中 → FAIL（设备已出站）

**条件：**

* StickerSN != DeviceSN
* DeviceSN ∈ 历史 PASS 绑定表

**结论：**

* FAIL

**错误类型：**

* `DeviceSN_AlreadyPassed`

**含义：**

* 已出站设备再次进入产线

**处理方式：**

* 停止流程
* 人工介入检查

---

### 规则 5️⃣：绑定不一致，且双方均无历史 PASS 绑定 → FAIL（包装不一致）

**条件：**

* StickerSN != DeviceSN
* StickerSN ∉ 历史 PASS 绑定表
* DeviceSN ∉ 历史 PASS 绑定表

**结论：**

* FAIL

**错误类型：**

* `Sticker_Device_Mismatch`

**操作指引：**

* 更换 StickerSN
* 重新扫描

---

## 5. 明确不处理的情况（刻意排除）

以下情况 **不在本系统职责范围内**：

* 仅扫描设备、不扫描贴纸
* 基于 FAIL 记录的重复判断
* 自动修复贴纸或设备
* 人工 override PASS 结果

---

## 6. 工程实现提示（给开发 & AI）

* 历史绑定表只存：

  * `StickerSN`
  * `DeviceSN`
  * `BatchId`
  * `Timestamp`
  * `Result = PASS`

* 所有校验逻辑：

  * 必须严格按照 **规则 1 → 5** 的顺序
  * 不允许自行添加隐式判断
