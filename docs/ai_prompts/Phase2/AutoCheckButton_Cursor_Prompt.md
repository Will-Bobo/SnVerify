# UI_Cursor_Prompt.md

> 模块：UI / View
> 目标：Phase 2 完整执行级 Cursor Prompt
> 存放路径：`docs/ai_prompts/Phase2/UI_Cursor_Prompt.md`

---

## 一、角色与职责

* **角色**：Cursor Agent 为主要开发者
* **职责**：

  * 构建界面布局，包括批次区、检验区域、日志区域、状态栏
  * 显示 PASS/FAIL、错误信息、批次状态、日志状态
  * 绑定 Snapshot 状态给 ViewModel
* **边界**：

  * 不包含业务逻辑或流程处理
  * UI 控件仅用于展示和用户交互

---

## 二、模块目标

* **输入**：Snapshot 对象、批次对象、日志消息
* **输出**：界面状态显示更新
* **功能点**：

  1. 中间检验区域显示当前 SN 校验状态
  2. 批次输入区域显示批次号、开始/结束按钮
  3. 测试记录区域可切换显示，默认关闭
  4. 日志区域可切换显示，默认关闭
  5. 状态栏显示全局状态
  6. 扫码枪输入绑定文本框，完成扫描后清空
* **接口**：

  * 绑定 Snapshot 对象
  * 命令绑定按钮（StartBatch, EndBatch, AutoCheck）

---

## 三、架构与约束

* **MVVM 分层约束**：

  * View 只负责展示和命令绑定
  * 不包含业务逻辑或流程控制
* **线程与调度**：

  * 所有 Snapshot 绑定更新在 UI 线程自动处理
* **UI 控件约束**：

  * 扫码枪文本框必须绑定数据接收事件
  * 界面控件遵循简约大方设计，操作员易于使用

---

## 四、单元测试要求（TDD）

* **正常路径测试**：

  1. Snapshot 状态更新 → 界面显示正确
  2. 批次开始/结束 → 批次区域状态正确
  3. 测试记录区域显示切换正常
  4. 日志区域显示切换正常
* **异常路径测试**：

  1. Snapshot 异常 → 界面错误提示
  2. 扫码枪文本框异常 → 不影响其他控件
* **边界条件**：

  * 批次号为空
  * 高速扫码输入更新显示测试

---

## 六、输出要求

1. 生成 UI 界面 XAML / code-behind
2. 界面控件绑定 Snapshot 和命令
3. 支持批次、检验区、日志区、状态栏功能
4. Snapshot 更新正确反映到界面

---

## 七、完成判定标准

* Snapshot 与界面绑定正确，刷新正常
* 批次开始/结束按钮功能正确
* 日志和测试记录显示正确
* 异常路径可正确捕获且界面显示错误信息
