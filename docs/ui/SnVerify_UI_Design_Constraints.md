# SnVerify 工业上位机 UI 设计约束（Phase 2.x）

> 本文用于**约束 AI（Cursor Agent）生成 UI 的方式**，避免偏 Web / Demo 风格，确保符合产线工业上位机的使用习惯。
>
> 目标不是“好看”，而是：**稳定、可读、低误操作、可快速判断结果**。

---

## 一、UI 设计总目标（不可违反）

1. 操作员在 **3 秒内** 能判断：

   * 当前状态（空闲 / 检验中 / PASS / FAIL）
   * 是否可以换机
2. 扫码 → 检验 → 换机的主流程 **不依赖鼠标**
3. 所有非核心信息 **默认折叠 / 弱化**

---

## 二、页面结构约束（Layout Rules）

### 1. 页面分区（固定结构）

页面必须包含以下区域，顺序不可打乱：

1. **批次控制区（顶部，次要）**
2. **主检验区（中部，核心区域）**
3. **辅助功能区（自检 / 手动触发）**
4. **日志 / 测试记录区（默认折叠）**
5. **全局状态栏（窗口最底部）**

---

### 2. 主检验区约束（最重要）

* 主检验区高度 ≥ 窗口高度的 **60%**
* 居中显示，不可被日志、列表挤占
* 必须包含：

  * 当前状态（WAIT / PROCESSING / PASS / FAIL）
  * 当前 SN
  * 失败原因（仅 FAIL 时显示）

---

## 三、颜色与视觉规范（Visual Rules）

### 1. 状态颜色（强制）

| 状态         | 颜色    | 说明        |
| ---------- | ----- | --------- |
| WAIT / 空闲  | 灰色    | 无操作、等待扫码  |
| PROCESSING | 蓝色    | 正在检验，不可操作 |
| PASS       | 高饱和绿色 | 明确可换机     |
| FAIL       | 高饱和红色 | 明确禁止流转    |

> 禁止使用渐变、阴影、动画

---

### 2. 字体与排版

* 主状态文字字号 ≥ 48
* SN 显示字号 ≥ 20
* 失败原因字号 ≥ 16
* 不使用花体、不使用细字体

---

## 四、控件行为约束（Interaction Rules）

### 1. 批次控制区

* 批次名默认自动生成（batch_YYYYMMDD_HHMMSS）
* 批次名 **可编辑**，但开始后不可编辑
* 按钮状态规则：

| 状态  | 开始 | 结束 | 导出 |
| --- | -- | -- | -- |
| 未开始 | 可用 | 禁用 | 禁用 |
| 进行中 | 禁用 | 可用 | 禁用 |
| 已结束 | 可用 | 禁用 | 可用 |

---

### 2. 扫码与手动触发

* 扫码枪为主路径（无需点击）
* 手动“开始检验”按钮仅作为兜底
* 扫码输入框：

  * 可隐藏或弱化
  * 必须始终可接收焦点

---

### 3. 自检按钮（明确定位）

> 自检不是“跑一遍完整检验流程”

自检只用于：

* ADB 是否可用
* 是否检测到多设备
* MES 接口是否可达（若开启）

自检结果：

* 输出到日志区
* 不影响批次状态

---

## 五、日志与记录区规范

### 1. 默认行为

* 页面加载时默认 **折叠**
* 不影响主检验区尺寸

### 2. 内容要求

* 时间戳
* 模块名（Scan / ADB / MES / Storage）
* 关键信息

---

## 六、Cursor Agent 执行约束（非常重要）

当 Cursor Agent 被要求修改 UI 时，必须遵循：

1. **只调整 XAML / Style / 布局**
2. 不新增业务逻辑
3. 不修改 Service / Domain 层
4. 所有改动以“工业上位机稳定性优先”为目标

---

## 七、适用阶段说明

* 本约束适用于：Phase 2.x / Phase 2.5
* 不适用于：Demo 展示 / 市场宣传版本

---
