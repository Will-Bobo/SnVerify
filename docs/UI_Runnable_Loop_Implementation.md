# UI 可运行闭环实现说明

## 当前 UI 能做什么

### ✅ 已实现的核心功能

1. **扫码输入触发校验**
   - 扫码枪输入 SN（键盘模拟）
   - Enter 键作为结束符触发校验流程
   - 输入框自动聚焦，方便扫码枪输入

2. **状态显示（操作员友好）**
   - **等待扫码**：灰色，48号字体，清晰可见
   - **正在检验...**：蓝色，48号字体
   - **PASS**：绿色，48号字体，一眼能分辨
   - **FAIL**：红色，48号字体，下方显示失败原因

3. **防御逻辑**
   - 处理中时，输入框自动禁用，忽略新的扫码输入
   - 批次未激活时，拒绝扫码（需要先开始批次）
   - 空字符串输入被忽略

4. **批次管理**
   - 开始批次：创建批次，启动日志服务
   - 结束批次：结束批次，停止日志服务
   - 批次状态显示在状态栏

5. **状态栏信息**
   - 当前批次号
   - 当前状态（等待扫码 / 正在检验... / PASS / FAIL）
   - 当前 SN

6. **校验完成后自动清空**
   - 校验完成后，输入框自动清空
   - 可以继续扫下一台设备

### 🔄 最小闭环流程

1. ✅ 程序启动
2. ✅ 扫码枪输入 SN（键盘模拟）
3. ✅ Enter 作为结束符
4. ✅ 触发校验流程
5. ✅ UI 明确进入"正在检验..."
6. ✅ 校验完成
7. ✅ UI 明确显示 PASS 或 FAIL
8. ✅ FAIL 时显示失败原因
9. ✅ 输入框自动清空
10. ✅ 可继续扫下一台

## 被刻意延后的能力

### ⏸️ UI 美化
- 当前 UI 只追求功能可用，不追求美观
- 配色系统、动画效果、图标等延后

### ⏸️ 测试记录区域
- 测试记录列表显示功能延后
- 当前只显示当前 SN，不显示历史记录

### ⏸️ 日志区域
- 日志实时显示功能延后
- 日志已写入文件，但不在 UI 中显示

### ⏸️ 异常弹窗
- 异常提示目前只更新状态，不弹窗
- 未来可以添加异常弹窗提示

### ⏸️ 依赖注入容器
- 当前使用简单的 ServiceFactory
- 未来应该使用 Unity、Autofac 等依赖注入容器

### ⏸️ Snapshot 事件机制
- 当前使用轮询方式更新 Snapshot
- 未来应该使用事件机制，提高效率

### ⏸️ 扫码枪扩展支持
- 当前只支持 Enter 作为结束符
- 如果未来扫码枪不发 Enter，可以扩展为：
  - 监听 TextChanged 事件，检测特定字符（如 Tab）
  - 或使用定时器，检测输入停顿

## 技术实现说明

### 扫码输入触发机制

**当前实现**：
- 监听 `KeyDown` 事件
- Enter 键触发 `HandleScanInputAsync`
- Enter 之前的全部内容 = SN

**扩展方案**（未实现）：
- 如果扫码枪不发 Enter，可以：
  1. 监听 `TextChanged` 事件，检测特定字符（如 Tab）
  2. 使用定时器，检测输入停顿（如 500ms 无输入视为完成）

### Snapshot 更新机制

**当前实现**：
- 使用轮询方式（`while (_verificationFlowService.Snapshot.IsProcessing)`）
- 每 100ms 轮询一次，直到处理完成

**未来改进**：
- 使用事件机制（`SnapshotChanged` 事件）
- 提高效率，减少轮询开销

### 批次管理

**当前实现**：
- 批次未激活时，拒绝扫码
- 需要先点击"开始批次"按钮

**未来改进**：
- 可以自动开始批次（如果批次未激活，自动创建并开始）
